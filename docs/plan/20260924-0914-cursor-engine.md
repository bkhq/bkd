## Context

Cursor CLI 2026.09.23-86fc751 was installed for this task into
`~/.local/share/cursor-agent/versions/<v>/` with only the `~/.local/bin/cursor-agent`
link created: the official installer also replaces `~/.local/bin/agent`, which on
this host is grok's alias. Note that **every `cursor-agent` run rewrites
`~/.local/bin/agent` to point at itself**; BKD resolves `grok` by name so it is
unaffected, but the shell alias is. Logged in via `NO_OPEN_BROWSER=1 cursor-agent login`.

Verified headless protocol (`cursor-agent -p <prompt> --output-format stream-json --force --trust --workspace <dir>`):

- NDJSON, every event carries `session_id`:
  - `system/init` (`apiKeySource`, `cwd`, `session_id`, `model`, `permissionMode`)
  - `user` (echo of the prompt)
  - `thinking` with `subtype: 'delta'` + `text`, then `subtype: 'completed'` —
    emitted even without `--stream-partial-output` (docs say suppressed; they are not)
  - `assistant` whole messages (`message.content[].text`); the ones flushed before a
    tool call also carry `model_call_id` + `timestamp_ms`
  - `tool_call` `started`/`completed` with `call_id` (contains a literal `\n`) and
    `tool_call.<variant>.{args,result}`; observed variants: `shellToolCall`
    (`args.command`, result `success.{stdout,stderr,exitCode,...}`), `readToolCall`
    (`args.path`, `success.content`), `editToolCall` (used for both create and edit:
    `args.path`, `args.streamContent`, `success.{diffString,message,linesAdded,linesRemoved}`),
    `grepToolCall` (`args.pattern`, `args.path`, `success.workspaceResults[dir].content.matches[]`),
    `globToolCall` (`args.globPattern`, `args.targetDirectory`, `success.files[]`),
    `getMcpToolsToolCall`. Documented but not observed: `writeToolCall`, `deleteToolCall`.
    There is no list-directory tool.
  - `result` (`subtype`, `is_error`, `duration_ms`, `result` = concatenation of all
    assistant texts, `request_id`, `usage.{inputTokens,outputTokens,cacheReadTokens,cacheWriteTokens}`)
- Sessions: `--resume <uuid>` **creates** the session when the id is unknown and
  resumes it otherwise, so BKD's pre-generated `externalSessionId` can be passed on
  the first turn exactly like grok's `-s`. `create-chat` is not needed (and it hangs
  when stdin is an inherited pipe; all subprocesses must use `stdin: 'ignore'`).
- Cancel: SIGTERM exits within ~2s, no `result` line, and the session resumes with
  context afterwards. A shell command still running inside the turn is orphaned.
- Errors: an unknown `--model` exits 1 with the message on stderr and no stdout.
- Discovery: `--version` prints `2026.09.23-86fc751`; `status --format json` gives
  `{status: 'authenticated'|'unauthenticated', isAuthenticated, userInfo?}`;
  `models` prints `Available models` then `<id> - <label>[ (default)]` lines.
- Binary: `~/.local/bin/cursor-agent` (legacy name, always created by the installer)
  is the safe lookup; `agent` is ambiguous on hosts that also run grok.

BKD side: unchanged from the grok integration (commit b8fb789) — `EngineExecutor`
in `engines/types.ts`, registry in `executors/index.ts`, pipeline keyed on
`subtype: 'init'`, `turnCompleted`, `resultSubtype`, `isError`
(`failure-detect.ts` treats `metadata.isError` as a logical failure, so failed
tool results must not set it), `inputTokens`/`outputTokens`.

## Proposal

1. `engines/executors/cursor/executor.ts` — `CursorExecutor`:
   - `engineType: 'cursor'`, `protocol: 'stream-json'`, `capabilities: []`.
   - `resolveBinary()`: `cursor-agent` on PATH, then `~/.local/bin/cursor-agent`.
   - `buildCursorArgs`: `-p --output-format stream-json --force --trust
     --workspace <cwd> --resume <sessionId ?? externalSessionId> [--model <m>] <prompt>`.
   - stdin `ignore`; `cancel` = SIGTERM, SIGKILL after 5s.
   - `getAvailability`: version from `--version`, auth from `status --format json`.
   - `getModels`: `parseCursorModels` over `models` output; fallback `auto`.
2. `engines/executors/cursor/normalizer.ts` — `CursorLogNormalizer`, self-contained:
   - `init` → system-message with `subtype: 'init'`, `sessionId`, `model`, `cwd`.
   - `user` → dropped. `thinking` deltas accumulated, one `thinking` entry on `completed`.
   - `assistant` → `assistant-message`.
   - `tool_call/started` → `tool-use` + `ToolAction` (`read`→file-read,
     `edit`/`write`/`delete`→file-edit, `shell`→command-run, `grep`/`glob`/`ls`/
     `semSearch`/`webSearch`→search, `webFetch`→web-fetch, `updateTodos`→task-plan,
     others → generic `tool`); `completed` → result entry decoded per variant,
     `result.error`/`rejected` → `error-message` (no `isError` metadata).
   - `result` → `turnCompleted`, `resultSubtype`, `isError`, `duration`, `sessionId`,
     `inputTokens` (= input + cache read + cache write), `outputTokens`; the
     `result.result` text is emitted only when no assistant text was seen.
3. Wire `'cursor'` into `EngineType` (shared + api), `BUILT_IN_PROFILES.cursor`
   (`baseCommand: 'cursor-agent'`), the registry, `ALL_ENGINE_TYPES`, `RESERVED_IDS`,
   `validEngines`, safe-env (`CURSOR_API_KEY`).
4. Frontend: `CursorIcon` in `EngineIcons.tsx`.
5. Docs: `CLAUDE.md`, `docs/architecture.md`, changelog.
6. Tests (RED first): `test/fixtures/cursor-session.jsonl` from the real transcript;
   `test/cursor-normalizer.test.ts`; `test/cursor-executor.test.ts` (args, models,
   status parsing).

Out of scope: partial-output streaming, local session browser/import, virtual
engines based on cursor, slash-command discovery, MCP approval, interactive
permissions, plan mode.

## Risks

- `--force` bypasses every permission policy, like grok in headless mode.
- A shell command running when the turn is cancelled keeps running (CLI behaviour).
- `call_id` values contain a newline; they are opaque ids and stored as-is.
- The `models` and `status` text formats are undocumented; parsing is lenient and
  falls back to `auto` / `unknown`.

## Scope

~14 files: 3 new source files, 2 test files + fixture, ~8 one-line union edits,
frontend icon, CLAUDE.md/architecture/changelog. No DB schema change, no new dependency.

## Alternatives

- `create-chat` before the first turn: unnecessary since `--resume` creates unknown ids.
- ACP mode (`agent acp`, hidden): long-lived JSON-RPC with mid-turn messages and
  permission prompts; needs a new protocol layer (removed in ENG-003). Deferred.
