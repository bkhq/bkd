## Context

Grok Build (`grok`, xAI, v1.0.41, Rust) is installed at `~/.local/bin/grok` and
signed in via grok.com OAuth. `grok models` lists `grok-4.7` (default).

Probed behavior of headless mode (`grok -p <prompt> --output-format streaming-messages-json`):

- NDJSON in the Anthropic Messages wire shape: `system/init` (carries
  `session_id`, `model`, `cwd`, `tools`, `slash_commands`) → `assistant`
  (content blocks `thinking` / `text` / `tool_use`) → `user` (`tool_result`)
  → `result` (`subtype`, `is_error`, `stop_reason`, `result`, `usage`,
  `total_cost_usd`, `modelUsage.<model>.contextWindow`).
- `--include-partial-messages` adds `stream_event` delta lines.
- `-s <uuid>` names a new session and `init` echoes it; `-r <uuid>` resumes
  with context intact and the same session ID.
- `--permission-mode bypassPermissions` runs read/write/shell tools unprompted.
- No stdin input channel (no `--input-format`): one prompt per process, the
  process exits after the turn.
- SIGTERM exits 143 with no `result` line; the session is saved up to the last
  completed tool call.
- Tool names differ from Claude: `read_file`, `write`, `search_replace`,
  `run_terminal_command`, `grep`, `list_dir`, `todo_write`, `spawn_subagent`,
  `web_search`, `web_fetch`, `ask_user_question`, `get_command_or_subagent_output`, ...
- `tool_result.content` is a JSON string with a typed payload, e.g.
  `{"type":"ReadFile","FileContent":{...}}`,
  `{"type":"Bash","output_for_prompt":"exit: 0\n...","exit_code":0,...}`,
  `{"type":"BackgroundTaskStarted",...}`, `{"type":"TaskOutput",...}`.
- It loads `~/.claude` CLAUDE.md and skills, so its behavior tracks Claude's.

BKD side:

- Executors implement `EngineExecutor` (`engines/types.ts`) and are registered in
  `engines/executors/index.ts`.
- The stream pipeline is engine-agnostic and keys on normalized metadata:
  `turnCompleted` / `resultSubtype` (turn over, `issue/streams/classification.ts`),
  `isError` (failure detection), `inputTokens` / `outputTokens` / `costUsd`
  (`pipeline/token-usage.ts`), context-usage metadata, `streaming` for deltas,
  `subtype: 'init'` (turn restart).
- `EngineType` is a closed union duplicated in: `packages/shared/src/index.ts`,
  `engines/types.ts` (+ `BUILT_IN_PROFILES`), `engines/issue/queries.ts`,
  `engines/virtual-engines.ts`, `routes/settings/general.ts`,
  `openapi/schemas.ts`, `openapi/routes.ts`, `openapi/extra-schemas.ts`,
  `engines/safe-env.ts`, frontend `EngineIcons.tsx`.

## Proposal

1. `engines/executors/grok/executor.ts` — `GrokExecutor`:
   - `protocol: 'stream-json'`, capabilities `['context-usage']`.
   - Base args: `-p <prompt> --output-format streaming-messages-json
     --include-partial-messages --permission-mode bypassPermissions`, `cwd` set
     on the spawn, `-m <model>` when not `auto`, `GROK_DISABLE_AUTOUPDATER=1`.
   - `spawn`: `-s <externalSessionId>`; `spawnFollowUp`: `-r <sessionId>`.
   - stdin `ignore`; no protocol handler. `cancel` sends SIGTERM (`subprocess.kill()`).
   - `getAvailability`: resolve `grok` binary (PATH, then `~/.local/bin`,
     `~/.grok/bin`), `grok --version`, auth from `XAI_API_KEY` or
     `$GROK_HOME|~/.grok/auth.json`.
   - `getModels`: static `[{ id: 'grok-4.7', isDefault: true }]`.
2. `engines/executors/grok/normalizer.ts` — `GrokLogNormalizer`, self-contained
   (no import from `executors/claude/`; mirrors its approach where useful):
   - `system/init` → system-message with `subtype: 'init'`, session ID, model.
   - `assistant` blocks → `assistant-message` / `thinking` / `tool-use`
     entries, tool-name → `ToolAction` map (`read_file`→file-read,
     `write`/`search_replace`→file-edit, `run_terminal_command`→command-run,
     `grep`/`list_dir`→search, `web_fetch`→web-fetch, `spawn_subagent`→agent,
     `todo_write`→task-plan, others → generic `tool`).
   - `user.tool_result` → tool result entry, decoding the JSON payload into
     readable text (`output_for_prompt`, file content, etc.), falling back to raw.
   - `stream_event` text/thinking deltas → `streaming: true` entries.
   - `result` → `turnCompleted`, `resultSubtype`, `isError`, `inputTokens`,
     `outputTokens`, `costUsd`, context window.
3. Wire `'grok'` into every `EngineType` touchpoint listed above; `safe-env`
   passes `XAI_API_KEY`, `GROK_HOME`; `BUILT_IN_PROFILES.grok` with
   `baseCommand: 'grok'`.
4. Frontend: Grok icon in `EngineIcons.tsx`; any engine label i18n keys in
   `en.json` and `zh.json`.
5. Tests (RED first): normalizer fixtures from the probe transcripts
   (init, text, thinking, each mapped tool, tool_result decoding, deltas,
   result success/error); executor arg assembly for spawn / follow-up / model;
   availability parsing.

Out of scope: mid-turn message injection, interactive permission approval /
plan mode, session browser (`sessions/`), slash-command discovery, usage panel.

## Risks

- `streaming-messages-json` is a compatibility layer; field drift across grok
  releases could break parsing. Mitigation: normalizer degrades unknown
  blocks to generic entries instead of dropping or throwing.
- Cancel produces no `result`; relies on the existing exit-code path to mark
  the session cancelled — verify in the E2E run.
- Pending messages queued during a turn only go out on the next `-r` spawn
  (same as Claude's post-turn path), not mid-turn.
- Bypass permissions is always on for Grok; a supervised policy is not honored.

## Scope

~10 files: 2 new (executor, normalizer) + index, ~8 one-line union edits,
frontend icon + i18n, 2 new test files. No DB schema change.

## Alternatives

- ACP (`grok agent stdio`, JSON-RPC, long-lived): allows mid-turn messages and
  permission requests, but needs a new protocol layer (the old ACP engine was
  removed in ENG-003). Deferred.
- `--output-format streaming-json` (native ACP session updates): xAI-native,
  but a new shape to map; the messages format is closer to what the pipeline
  already consumes.
