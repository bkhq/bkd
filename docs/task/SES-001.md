# SES-001 Scan local engine sessions and import them as issues

- **status**: completed
- **priority**: P1
- **owner**: roy
- **createdAt**: 2026-08-22 07:05

## Description

Add a global view that scans Claude Code and Codex sessions stored on the host
outside BKD, and lets an operator turn any of them into an issue attached to a
chosen project.

Acceptance criteria:

- A global `/sessions` page lists local sessions for both engines with title,
  working directory, last-active time, size and CLI version, newest first,
  with engine filter and search.
- Sessions already bound to a BKD issue are marked as managed and link to it.
- Codex subagent rollout threads are excluded from the top-level list.
- A session can be previewed as a normalized transcript before import.
- Importing creates an issue in the selected project with the session id stored
  as `external_session_id`, the first user message as the prompt, and the
  transcript backfilled into the issue log.
- Import is rejected when the session is already bound to an issue, and warns
  when the session working directory does not match the project path.
- Path traversal outside the configured session roots is rejected.
- Focused API and frontend tests pass, followed by repository lint, typecheck
  and build verification.

## Notes

Investigation is recorded in PLAN-017. Verified corpus on this host: 178 Claude
transcripts (167 MB) under `~/.claude/projects/`, 518 Codex rollouts (428 MB)
under `~/.codex/sessions/`, of which 89 are subagent threads. Listing must stay
metadata-only.

- 2026-08-22 07:20 — PLAN-017 approved; implementation started.
- Decision: list cwd-matching and non-matching sessions together; the user picks the import mode (full transcript or link only) and acknowledges a cwd mismatch.
- 2026-08-22 07:38 — Implementation and verification completed.
- Deviation from PLAN-017: the Codex rollout reader maps `event_msg` /
  `response_item` payloads directly instead of reusing `CodexLogNormalizer`,
  which only accepts app-server JSON-RPC notifications.
- The head-read window is 256 KB, not 64 KB. Measured on the real corpus: the
  smaller window left 62 of 612 sessions without a title; 256 KB leaves 29, of
  which 28 contain no user prompt at all.
- No path traversal surface: `read` resolves a record produced by the scan, so
  no on-disk path is ever derived from client input.
