## Description

Both READMEs still describe the pre-lode world. Following them today produces an
install that never updates.

- The Installation section downloads `bkd-launcher-*` from the `launcher-v1`
  release. REL-003 replaced that supervisor with [lode](https://github.com/dotns/lode),
  and REL-002 renamed the package to `bkd-server.tar.gz`. The launcher selects
  its update with `name.startsWith('bkd-app')`, so a fresh launcher install finds
  no matching asset and sits on whatever it first downloaded. The release page
  says as much; the README does not.
- "Auto-Upgrade — Automatic version checking and one-click upgrade from the
  settings UI" is wrong in both directions: BKD no longer updates itself, and
  update policy is owned by the operator through `lode.toml`.
- `ROOT_DIR` is documented as "Workspace root directory". It pins the install
  root so `data/` survives an upgrade — unrelated to the agent workspace.
- The feature list predates the cron scheduler, git worktrees, the process
  manager, subagent observability and local session import.

Acceptance criteria:

- Installation matches `docs/deployment.md`, including the migration path for an
  existing launcher install.
- No documented feature or variable contradicts the code.
- `README.md` and `README.zh-CN.md` stay in sync.
