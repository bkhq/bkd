# ENG-020 Add Claude subscription usage panel in settings

- **status**: completed
- **priority**: P2
- **owner**: roy
- **createdAt**: 2026-06-07

## Problem

The Claude CLI exposes subscription rate-limit utilization (the TUI `/usage`
panel: 5-hour session window and 7-day window) via an internal endpoint
`GET https://api.anthropic.com/api/oauth/usage`. BKD has no way to surface this;
users must drop to the terminal and run the interactive client to see how much
of their plan is left.

## Approach

Proxy the endpoint server-side and render it as a new section in the app
settings dialog.

- **Backend**: `GET /api/engines/claude/usage` reads the OAuth `accessToken`
  from `~/.claude/.credentials.json` (`claudeAiOauth.accessToken`), calls the
  upstream endpoint with `Authorization: Bearer <token>` and
  `anthropic-beta: oauth-2025-04-20`, and returns a normalized envelope with
  graceful unavailable states (no credentials / api-key mode / expired token /
  upstream error). The token is never returned to the client, logged, or stored.
- **Frontend**: a new `usage` nav item + `UsageSection` in `AppSettingsDialog`
  showing 5h / 7d utilization bars and reset times, with a manual refresh and a
  friendly unavailable message.

## Scope

- `apps/api`: `routes/engines.ts` (new handler), `openapi/routes.ts` (route def
  + response schema), a small `engines/claude/usage.ts` helper.
- `packages/shared`: `ClaudeUsage` types.
- `apps/frontend`: `lib/kanban-api.ts`, `hooks/use-kanban.ts`,
  `components/settings/UsageSection.tsx`, `AppSettingsDialog.tsx` nav wiring,
  `i18n/{en,zh}.json`.

## Out of scope

- OAuth token auto-refresh.
- usage-credits (spend/balance) page.
- Historical usage persistence / trend charts.

## Verified response shape

Live probe (200) showed the upstream returns rate-limit windows at the **top
level** (no `rate_limits` wrapper), and each window's percentage field is
`utilization` (0–100), not `used_percentage`:

```jsonc
{
  "five_hour":   { "utilization": <0-100>, "resets_at": <iso> },
  "seven_day":   { "utilization": <0-100>, "resets_at": <iso> },
  "seven_day_opus": null,            // per-model windows; null when inactive
  "seven_day_sonnet": { ... },
  "extra_usage": { "monthly_limit", "used_credits", "utilization", ... }
}
```

The helper parses top-level `five_hour` / `seven_day` `.utilization`. Per-model
windows and `extra_usage` credits are out of scope for this task.

## Risks

- Endpoint is undocumented; defensive parsing, missing fields must not crash.
- Only works for subscription (Pro/Max) OAuth login, not API-key billing.
- BKD reads the credentials file directly; a stale token yields 401 → surfaced
  as an unavailable state advising the user to re-auth in the terminal.
