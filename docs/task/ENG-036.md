# ENG-036 Turn settlement misreads subagent and background-task signals

- **status**: completed
- **priority**: P1
- **owner**: roy
- **createdAt**: 2026-08-31 00:00

## Description

Settlement to `review` is driven by `isTurnCompletionEntry()`
(`engines/issue/streams/classification.ts:15-19`), which accepts any entry
carrying `metadata.turnCompleted` or a `resultSubtype` key. Three signals of very
different authority can set that flag, and the first one to arrive wins:

- Claude `type: 'result'` (`executors/claude/normalizer.ts:786`)
- Claude `system/session_state_changed state: 'idle'` (`normalizer.ts:228`) —
  the CLI's authoritative turn-over signal, emitted only after the background
  agent loop exits
- Codex `turn/completed`

Two failure classes follow:

**A. Subagent-scoped signals end the main turn.** `parseResult` sets
`turnCompleted` unconditionally, and `ClaudeResult` / `ClaudeSystem`
(`normalizer-types.ts`) declare no `parent_tool_use_id`, so a forwarded
subagent-scoped `result` or `idle` is indistinguishable from the main thread's.
`tagSubagent` (`normalizer.ts:58`) only covers assistant/user envelopes.

**B. The background-task loop settles early and can never reopen.** With
`Agent(run_in_background)` / `Bash(run_in_background)` the CLI emits `result`,
then later drives another model turn off `task_notification`. BKD settles on the
first `result`; the second one is swallowed by the duplicate guard
`if (!managed.turnInFlight) return` (`lifecycle/turn-completion.ts:29`), so the
issue sits in `review` while the engine keeps producing output. Nothing tracks
outstanding tasks today: `task_started` (`normalizer.ts:167`), `task_progress`
and `task_notification` are normalized into log entries only, and
`background_tasks_changed` is dropped.

## ActiveForm

Fixing turn settlement for subagent and background-task signals

## Scope

- Attribute turn-completion signals to the main thread: reject entries carrying
  `parent_tool_use_id` / `metadata.subagent`, or a `session_id` other than the
  one from `init`.
- Track outstanding subagent/background tasks and hold settlement while the set
  is non-empty, with a bounded timeout so a lost notification cannot pin an
  issue in `working`.
- Rank the Claude signals instead of taking the first: `result` arms the settle
  timer, `session_state_changed: idle` fires it immediately, timer expiry is the
  fallback for CLIs that never emit `idle`.
- Allow a settled-but-not-exited turn to reopen when main-thread activity
  resumes, reverting only a `review` state this execution auto-set.

## Out of scope

- Detached background processes the agent starts itself (tmux, nohup, dev
  servers). The CLI turn is genuinely over; `review` is correct and settlement
  must not wait on them. They stay visible through the process drawer.
- Codex settlement: `turn/completed` is emitted by the app-server per turn and
  is already authoritative.
- Reworking stall detection, idle GC, or the reconciler.

- 2026-08-31 investigation, CLI 2.1.251, `-p --output-format=stream-json
  --verbose --input-format stream-json --forward-subagent-text`, captures kept
  in `/tmp/eng-036/probe-{subagent,bg,bgagent}.jsonl`:
  - **B confirmed.** A background task makes the CLI run two turns for one
    prompt. Observed order: `background_tasks_changed{tasks:[t]}` ->
    `task_started` -> `result{success,num_turns:2}` -> `background_tasks_changed
    {tasks:[]}` -> `task_updated` -> `task_notification{status:completed}` ->
    a second `system/init` on the same session_id -> assistant output ->
    `result{success,num_turns:1}`. BKD settles on the first `result`; the second
    is swallowed by the duplicate guard, so the issue stays in `review` for the
    rest of the run. With `Agent(run_in_background)` the subagent's own turns
    (tagged `parent_tool_use_id`) also stream in after the first `result`.
  - **`background_tasks_changed` is the authoritative live set** — full task
    list on every change, `tasks: []` when drained. Currently dropped by the
    normalizer. It, not a hand-rolled counter, should gate settlement.
  - **A not reproducible.** Every `result` in all three captures is main-thread:
    no `parent_tool_use_id`, no subagent-scoped `result`. Foreground subagents
    emit exactly one `result`, at the very end. The attribution filter is
    therefore defence-in-depth against a future CLI, not the live defect.
  - **`session_state_changed` never fires** in this mode, so the "authoritative
    idle signal" branch (`normalizer.ts:228`) is dead code on 2.1.251 and cannot
    be the primary settle trigger.
  - Probe artifact, no defect: streaming input rejects a bare-string `content`
    only when `--permission-prompt-tool stdio` is absent. With the flag BKD
    passes, `ClaudeProtocol.sendUserMessage`'s string form parses fine.
- 2026-08-31 implemented:
  - `background_tasks_changed` is normalized to `metadata.backgroundTasks` (ids
    only) and hidden from chat via `isVisible`, so it is a control signal the
    settle path reads and the UI never renders.
  - `handleTurnCompleted` withholds the completion while
    `managed.backgroundTasks` is non-empty. The CLI's follow-up turn settles
    normally; if the set drains without one, `BG_TASK_DRAIN_GRACE_MS` (3s)
    settles it; `BG_TASK_HOLD_MS` (10 min) caps a set that never drains.
  - `handleTurnRestarted` reopens a settled turn on a live process when the CLI
    re-emits `init`, and `revertAutoReview` puts the issue back to `working` —
    only if this execution is the one that auto-moved it.
  - `isTurnCompletionEntry` now rejects subagent-tagged entries (defence in
    depth; no CLI observed emitting one).
  - The hold is skipped when an interrupt is in flight, so a cancel settles
    immediately instead of waiting on tasks the user has stopped caring about.
  - Consequence, accepted: a follow-up typed while a background task runs is
    queued (the turn is still in flight) and flushed when the hold resolves,
    instead of dispatching against a turn the CLI has not really finished.
  - `register()` takes a `TurnStreamHooks` object instead of a bare
    `onTurnCompleted` callback; four call sites updated.
  - `test/fixtures/claude-background-tasks.jsonl` is the trimmed real capture;
    `test/claude-background-turn.test.ts` replays it and locks the ordering.
  - Deliberate test change: `claude-subagent.test.ts` asserted
    `background_tasks_changed` normalized to zero entries. That behaviour is
    what this task removes, so the assertion was replaced by two tests for the
    new metadata.
