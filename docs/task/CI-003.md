# CI-003 Gate releases on CI

- **status**: completed
- **priority**: P1
- **owner**: roy
- **createdAt**: 2026-08-25 16:20

## Description

`release.yml` packages and publishes without running lint, typecheck or tests.
`ci.yml` only triggers on `pull_request` and `workflow_dispatch`, and this
repository pushes straight to `main`, so a tag can be released from a tree that
has never been checked — which is exactly how the Typecheck failure repaired in
[CI-002](CI-002.md) survived several releases.

Acceptance criteria:

- The release workflow runs the full CI suite before it packages anything.
- A failing check stops the release; nothing is published.
- The checks are not duplicated between the two workflows.
- A dry run (`workflow_dispatch` with no tag) exercises the same gate.

## ActiveForm

Gating releases on the CI suite.

## Notes

- `ci.yml` gains a `workflow_call` trigger and `release.yml` calls it as a job,
  so the check matrix stays defined once.
- Releases get slower by the length of a CI run. That is the point.
- 2026-08-25 16:20 — Requested directly by the user; implementation started.
- 2026-08-25 16:35 — Implementation and verification completed.
- The first dry run surfaced a separate pre-existing bug: `workflow_dispatch`
  with no tag sets `VERSION` to the branch name, which `package.ts` rejects, so
  the advertised dry-run mode had never worked. Fixed by falling back to `dev`,
  the value `package.ts` already accepts for this case.

## Verification

- Release dry run on `main` (`workflow_dispatch`, no tag): all five CI jobs ran
  and passed *before* `Build app package`, `Validate version` was skipped as
  designed, packaging succeeded, and `Create Release` was skipped.
- The earlier dry run proved the gate ordering: CI completed first, and when
  packaging failed nothing was published.
- Both workflows parse as YAML; the check matrix exists only in `ci.yml`.
