# REL-004 Add a lode migration script and deployment guide

- **status**: completed
- **priority**: P1
- **owner**: roy
- **createdAt**: 2026-08-24 00:00

## Description

Give existing launcher-based installs a lossless path onto lode, and document deployment
from scratch.

Acceptance criteria:

- `scripts/migrate-to-lode.ts` detects a launcher install via `data/app/version.json`,
  writes a `lode.toml` whose `dir` and `[env] ROOT_DIR` both point at the existing install
  root, and never moves or deletes `data/db`, `data/uploads` or any user data.
- The script defaults to a dry run, is idempotent, refuses to clobber an existing
  `lode.toml` without `--force`, and prints the `lode-cli seed` command that keeps the
  current version as a rollback target.
- `docs/deployment.md` covers install, the BKD `lode.toml` reference, key trust setup,
  first run, upgrade/rollback operations, env-var equivalents for the removed launcher
  flags, and the migration procedure.
- Tests cover the migration script's detection, dry-run and idempotency behaviour.

Completed 2026-08-24.

- `scripts/migrate-to-lode.ts`: dry-run by default, `--apply` writes `lode.toml` with
  `dir` and `[env] ROOT_DIR` pointed at the existing install root (so `data/` never
  moves) and packs the active version into `<root>/migration/bkd-server.tar.gz` for offline
  seeding; `--prune` removes only `data/app/` and `data/updates/`; `--force` is required
  to overwrite a config or migrate a root with no version pointer.

  config, packing, prune scope, refusal paths and overwrite protection.
- Verified with the real toolchain: the generated `lode.toml` parses in `lode-cli status`
  with the intended settings, and the packed archive seeds as a rollback target
  (`lode-cli versions` lists it) with `data/db` untouched.
- `docs/deployment.md` covers install, the annotated `lode.toml`, update policy, key
  trust, first run, systemd, CLI/UI operations, env-var replacements for the removed
  launcher flags, the migration procedure and troubleshooting.
