## Description

Projects have no classification dimension today. The home dashboard renders one flat,
manually sorted grid, and the only grouping that exists is the archived/active split.
Once the board holds more than a handful of projects, there is no way to separate, say,
work repos from experiments.

Add free-form tags to a project and let the dashboard filter by them.

Acceptance criteria:

- A project carries zero or more tags; tags are created inline while editing a project
  (no separate tag registry).
- Tags are settable on project create and project update, and are returned by every
  project read endpoint.
- The home dashboard can narrow the active project grid to a single tag, and each card
  shows its tags.
- Existing projects keep working with no tags; no data migration beyond the added column.
- API tests cover create/update/read of tags, including rejection of oversized input.

## Notes

Issues already implement exactly this shape: `issues.tag` is a single TEXT column holding a
JSON array, parsed by `parseTags` / `serializeTags` in `apps/api/src/routes/issues/_shared.ts`.
The project side should reuse that pattern rather than introduce a normalized tag table.
