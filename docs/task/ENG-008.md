# ENG-008 Add per-project default engine and model

- **status**: completed
- **priority**: P2
- **owner**: claude
- **createdAt**: 2026-05-15

## Description

Currently the default engine and model can only be configured globally
(`appSettings.defaultEngine` + `engine:<type>:defaultModel`). Add a
per-project override so each project can pin its own default engine and
model, falling back to the global default when unset.

`projects` already carries per-project overrides of the same shape
(`systemPrompt`, `envVars`), so the natural home is two nullable columns
on the `projects` table. `NULL`/empty means "inherit global".

## ActiveForm

Adding per-project default engine and model with global inheritance

## Scope

Decisions taken: only `ProjectSettingsDialog` (not CreateProjectDialog);
copy the existing engine/model selector pattern (no shared component
extraction — out of scope, tracked as possible follow-up).

- **DB**: `db/schema.ts` add `default_engine`, `default_model` (nullable);
  generated migration `0020`
- **Shared**: `packages/shared/src/index.ts` `Project` +
  `defaultEngine?`, `defaultModel?`
- **API**:
  - `openapi/schemas.ts` — `ProjectSchema` / `CreateProjectSchema` /
    `UpdateProjectSchema` add the two fields
  - `routes/projects.ts` — `serializeProject` + create/update persistence
  - `routes/issues/create.ts` — resolution chain: explicit body value >
    project default > global default > `claude-code`; keep registry
    coercion for stale/unsupported engine
- **Frontend**: `ProjectSettingsDialog.tsx` new Engine & Model section
  (reuses `useEngineAvailability/Profiles/Settings` + `EngineIcon`),
  explicit "inherit global" option; reuses existing `useUpdateProject`
- **i18n**: `en.json` + `zh.json`
- **Tests**: resolution precedence (4 layers + coercion) in
  `api-issues.test.ts`; project serialization round-trip
- **Docs**: `CLAUDE.md` data layer note; `docs/api/*` project fields

## Out of scope

- Extracting a shared `<EngineModelSelector>` component (possible
  follow-up refactor).
- Per-project default in the create-project flow (leave empty = inherit).

## Resolution precedence (issues/create.ts)

```
body.engineType ?? project.defaultEngine ?? global default ?? 'claude-code'
  -> then registry coercion (unsupported -> 'claude-code')
body.model ?? project.defaultModel ?? global engine default model
  -> ignore 'auto'
```

  global automatically; no data risk.
- Engine value persisted on a project is still coerced at issue-create
  time, so a later engine removal cannot create unrunnable issues
