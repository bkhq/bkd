# UI-004 Unify the panel resize handle

- **status**: completed
- **priority**: P2
- **owner**: roy
- **createdAt**: 2026-08-25 09:40

## Description

The drag-to-resize handle is implemented ten times across the frontend in three
mutually inconsistent variants, so behaviour and accessibility depend on which
panel the user happens to grab.

Current variants:

1. **Pointer + keyboard + ARIA** (7 copies) — `KanbanPage`, `LocalSessionsPage`,
   `NotesDrawer`, `TerminalDrawer`, `ProcessManagerDrawer`, `FileBrowserDrawer`,
   `FileBrowserPanel`. Byte-identical apart from `onPointerCancel`, which only
   `NotesDrawer` and `TerminalDrawer` have — everywhere else a cancelled pointer
   leaves the drag latched.
2. **Pointer only** (1 copy) — `DiffPanel`: no `role`, no `tabIndex`, no keyboard
   support, and a different hover treatment.
3. **Mouse only** (2 copies) — `IssueListPanel`, `ReviewListPanel`: driven by an
   `onResizeStart` callback that attaches `document` mousemove/mouseup listeners
   in `IssueDetailPage` and `ReviewPage`. No touch or pen support, no keyboard,
   `role="separator"` with none of the value attributes.

Acceptance criteria:

- One `ResizeHandle` component serves every panel, supporting both anchor edges.
- Every handle supports pointer drag (mouse, touch, pen), releases on pointer
  cancel, and supports keyboard resizing with the standard separator ARIA state.
- Width clamping stays with the caller, which already owns it (stores clamp in
  `setWidth`; the list pages clamp against a dynamic maximum).
- `IssueDetailPage` and `ReviewPage` drop their duplicated document-level
  mousemove/mouseup drag drivers.
- No visual regression in the drag affordance.
- Focused frontend tests pass, followed by repository lint, typecheck and build
  verification.

## Notes

- Recorded as a follow-up in [SES-003](SES-003.md); the user asked for the merge
  plus a survey of other inconsistent components.
- 2026-08-25 09:40 — Requested directly by the user; implementation started.
- 2026-08-25 10:05 — Implementation and verification completed.
- `components/ui/resize-handle.tsx` reports candidate widths and leaves clamping
  to the caller; `min`/`max` are the values reported to assistive technology.
- `LIST_MIN_WIDTH` / `LIST_MAX_WIDTH` moved to `IssueListPanel` — both pages had
  their own copies of the same two constants.
- `sessions.detail.resize` was renamed to `sessions.resizePanel` to match the
  `*.resizePanel` key used by every other panel.
- Behaviour change: the list panels no longer set `document.body.style.cursor`
  during a drag. Pointer capture already keeps events flowing to the handle, and
  none of the other eight panels did this.
