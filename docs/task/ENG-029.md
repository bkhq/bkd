# ENG-029 Engine probe cache never expires (stale Codex model catalog)

- **status**: completed
- **priority**: P1
- **owner**: claude
- **createdAt**: 2026-08-13

## Description

`getEngineDiscovery()` reads `probe:engines` / `probe:models` from
`app_settings` with no expiry, and `withFreshStaticModels()` only overlays
`claude-code` (whose catalog is static in code, ENG-024). For Codex — whose
catalog is discovered from the CLI — the DB copy is therefore pinned to
whatever the CLI advertised the first time it was probed, until someone hits
`POST /api/engines/probe` by hand.

Reproduced on a dev DB pinned at codex 0.132.0: the catalog still offered
`gpt-5.3-codex` and `gpt-5.2`, `model-resolver` accepted them as valid, and
the turn failed against the live CLI (0.144.3):

```
gpt-5.3-codex → thread/start OK → turn/completed status=failed
  400 invalid_request_error: The 'gpt-5.3-codex' model is not supported
  when using Codex with a ChatGPT account.
```

The reported engine version is stale for the same reason.

## Scope

- `db/helpers.ts` — persist a probe timestamp; `getProbeResults()` returns
  `null` once it is older than the DB TTL.
- `engines/startup-probe.ts` — DB entry treated as a cache with a TTL
  (6h) instead of permanent storage.
- `test/api-engines.test.ts` (or a new probe-cache test) — expiry behaviour.

## Out of scope

- Making the model catalog static in code for Codex — the CLI is the source
  of truth there.
