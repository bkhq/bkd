# ENG-030 Claude auth status is wrong on macOS; stale binary paths survive in cache

- **status**: completed
- **priority**: P2
- **owner**: claude
- **createdAt**: 2026-08-13

## Description

1. `getLocalClaudeAuthStatus()` decides the Claude auth badge from
   `ANTHROPIC_API_KEY` or the existence of `~/.claude/.credentials.json`.
   On macOS the CLI stores OAuth credentials in the login Keychain, so that
   file never exists and the engine is reported as `unauthenticated` even
   though it works. The heuristic also misses `CLAUDE_CODE_OAUTH_TOKEN`,
   `ANTHROPIC_AUTH_TOKEN`, `apiKeyHelper` and the Bedrock/Vertex providers.

   Claude Code ships an authoritative, cross-platform check:

   ```
   $ claude auth status --json
   {"loggedIn": true, "authMethod": "claude.ai", "apiProvider": "firstParty",
    "subscriptionType": "max", ...}
   ```

   It costs ~0.5s and only runs inside the engine probe, whose result is
   cached (memory 10 min / DB 6h, ENG-029).

   Impact is display-only: `authStatus` is rendered as a badge in
   `AppSettingsDialog.tsx` and gates nothing on the backend.

2. Cached probe entries keep a `binaryPath` that may no longer exist (this
   host had `/work/bin/claude` cached after the CLI moved to
   `~/.local/bin/claude`; production logged
   `ENOENT: posix_spawn '/work/bin/claude'`). ENG-029's TTL heals this within
   6h, but a missing binary should invalidate the cache immediately.

## Scope

- `executors/claude/executor.ts` — `parseClaudeAuthStatus()` (exported, pure)
  plus `queryClaudeAuthStatus()` running `claude auth status --json`, falling
  back to the env/file heuristic when the subcommand is unavailable.
- `executors/claude/index.ts` — export the parser for tests.
- `engines/startup-probe.ts` — `probeBinariesMissing()`; memory and DB cache
  tiers are skipped when a recorded binary is gone.
- `test/engine-availability.test.ts` — parser + staleness coverage.

## Out of scope

- Surfacing `authMethod` / `subscriptionType` in the UI.
- Codex auth detection (already live via `account/read`).
