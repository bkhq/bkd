# UI-010 Render file-browser Markdown with streamdown and drop react-markdown

- **status**: completed
- **priority**: P2
- **owner**: cd
- **createdAt**: 2026-09-09 04:30

## Description

After UI-008 the chat renders Markdown with streamdown, while the file
browser preview (`components/files/MarkdownRenderer.tsx`, used by
`FileViewer` for `.md` / `.mdx`) still uses react-markdown + remark-gfm +
github-markdown-css. Two renderers means two dependency sets and two visual
styles, and react-markdown drops the raw HTML that README files commonly use.

Switch `MarkdownRenderer` to `<Streamdown mode="static">` so both surfaces
share one component and one style, then remove the dependencies that only it
used.

Acceptance criteria:

- `.md` / `.mdx` preview renders headings, GFM tables, task lists, footnotes
  and inline HTML (`<p align="center"><img ...></p>`) via streamdown; script
  tags are stripped.
- Links render as plain anchors (link-safety modal disabled) opening in a new
  tab; fenced code goes through `ShikiCodeBlock`, shared with the chat.
- Relative image paths in a previewed file resolve against the file's own
  directory through the existing raw-file API, instead of the app origin.
- `react-markdown` and `github-markdown-css` are removed from
  `@bkd/frontend`; `.markdown-body` overrides are removed from `index.css`.
- Focused vitest cases pass, followed by the frontend suite, lint, typecheck
  and `bun run build`.

## Notes

- Approved by the user on 2026-09-09; same branch as UI-008/UI-009
  (`feat/ui-008-streamdown`).
- Shared `components/markdown-code.tsx` now holds the `code` / `inlineCode`
  overrides used by both `MarkdownContent` (chat) and `MarkdownRenderer`
  (file browser).
- Passing `rehypePlugins` to streamdown replaces its defaults, so the
  relative-image plugin is spliced in explicitly as
  `[raw, rewrite, sanitize, harden]`; it must run after rehype-raw (inline
  HTML images become elements) and before harden (which resolves relative
  URLs against the app origin and blocks bare relative ones).
- `FileViewer` gained an optional `root` prop; both callers pass
  `effectiveRoot`.
- PR #144 review follow-up: the relative-image plugin decoded nothing, so
  `URL.pathname` escapes were encoded a second time by `rawFileUrl`
  (`a%20b.png` -> `a%2520b.png`). Now the directory is encoded before URL
  resolution and each resolved segment is decoded once; malformed escapes
  stay literal.
- Found while fixing that: streamdown caches processors by plugin *name* +
  JSON options, so a per-file closure made every previewed file reuse the
  first file's directory. The plugin is now passed as a
  `[rehypeRelativeImages, { root, path }]` tuple.
- Second review round: `safeDecode` decoded whole segments, so one malformed
  escape kept valid `%20`s in the same name encoded. It now decodes only
  runs of well-formed `%XX` triplets and leaves everything else literal.
- `remark-gfm` was also removed as a direct dependency; streamdown carries it
  transitively.

- complete: Focused tests, frontend suite, lint, typecheck and build passed.
