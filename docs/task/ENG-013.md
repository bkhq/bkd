# ENG-013 Add virtual engines (claude-code + preset env vars)

- **status**: completed
- **priority**: P2
- **owner**: roy
- **createdAt**: 2026-05-22
- **plan**: PLAN-012

## Goal

Add user-defined **virtual engines** that run the real `claude-code`
executor with a preset set of environment variables injected (e.g.
`ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_MODEL`), so Claude
Code routes to a third-party Anthropic-compatible backend. Selectable like a
normal engine; at runtime it still spawns `claude-code`.

## Approach

See [PLAN-012](../plan/PLAN-012.md). Keep `issues.engine_type='claude-code'`
for virtual engines; persist the virtual id in a new
`issues.engine_profile_id` column; merge the profile's env at the four spawn
paths (profile overrides project env). Surface virtual engines through the
existing `/api/engines/available` + `/api/engines/profiles` so the create
dialog lists them with no special-casing.

## Scope

- shared: `VirtualEngine` type, `Issue.engineProfileId`.
- api: schema + migration, `virtual-engines.ts`, env merge in
  execute/restart/spawn, create resolution, engines routes (CRUD + discovery
  decoration), serializeIssue.
- frontend: api client + hooks, AppSettingsDialog management UI, display
  derive (`engineProfileId ?? engineType`), i18n.

## Result (verified)

Backend:
- shared: `VirtualEngine` type; `Issue.engineProfileId`.
- migration `0021_flowery_rockslide.sql` (adds `issues.engine_profile_id`);
  `db:generate` idempotent.
- `engines/virtual-engines.ts`: store (`getVirtualEngines` / `getVirtualEngine`
  / `setVirtualEngines` with validation), `resolveProfileEnvVars`, discovery +
  profiles decoration.
- env merge via `resolveExecEnvVars(engineProfileId, projectEnv)` (profile
  wins) at all four spawn paths: execute / restart / spawnRetry /
  spawnFollowUpProcess.
- `create.ts`: resolves a virtual id from body **or** project/global default →
  base engine + `engineProfileId` + preset model; widened `engineType`
  validation. `command.ts` execute maps virtual id → base engine.
- `engines.ts`: `GET` + `PUT /api/engines/virtual`; `/available` and
  `/profiles` decorated with virtual engines. OpenAPI schemas widened
  (`CreateIssue`, `ExecuteIssue`, `Issue.engineProfileId`).

Frontend:
- api client + `useVirtualEngines` / `useSetVirtualEngines` hooks.
- `AppSettingsDialog`: `VirtualEnginesSection` (id / name / model / env editor).
- `ChatBody` passes `engineProfileId ?? engineType` to `ChatInput`; `EngineInfo`
  falls back to the virtual engine's profile name.
- i18n keys (`settings.virtualEngine*`) in en + zh.

Verification:
- `bun run test:api`: 515 pass / 1 skip / 0 fail (incl. 7 new in

  api + frontend. `db:generate` idempotent.

## Known limitation

- `POST .../execute` with a virtual id maps to the base engine for spawn but
  does not persist `engineProfileId` on the issue; env injection relies on the
  id persisted at create time. Not reachable from the current UI.
- v1 supports only `baseEngine='claude-code'`.
