# SES-004 Delete local sessions from the scan list

- **status**: completed
- **priority**: P2
- **owner**: roy
- **createdAt**: 2026-08-26 19:20

## Description

The local sessions page can import a session but never remove one. Sessions whose
BKD issue was deleted still appear — the issue is soft-deleted, so it no longer
claims the session and the row returns to the unmanaged list — and there is no
way to clear them, so the list fills with noise.

Deleting here removes the CLI's own transcript from disk, not a BKD record.
`claude --resume` will no longer find the session afterwards, and nothing else
holds a copy. That makes it the most destructive action in the product, so it
needs an explicit confirmation that says what is being destroyed.

Acceptance criteria:

- Rows are multi-selectable, with a select-all for the current list.
- Deleting removes the transcript and, for Claude, the sidecar directory holding
  its subagent transcripts and spilled tool results.
- A session still bound to a live issue is refused, per item, so a bulk delete
  cannot silently break a working issue's follow-up.
- Confirmation states that the transcript is removed from disk and cannot be
  recovered, and names how many sessions are affected.
- The result reports per-session outcome; partial failure does not fail the whole
  request.
- Focused API and frontend tests pass, followed by repository lint, typecheck and
  build verification.

## Notes

- Paths still come from the scan, never from client input, so the traversal
  guarantee from SES-001 holds unchanged.
- Codex subagent rollouts spawned by a deleted thread are left on disk. They are
  excluded from the list, so they clutter nothing; deleting them would mean
  resolving `parent_thread_id` across the whole corpus on every delete.
- Deletion is real, not a soft flag: these are files BKD does not own, so there
  is no BKD-side place for a tombstone to live.
- 2026-08-26 19:20 — Requested directly by the user; implementation started.
- 2026-08-26 19:45 — Implementation and verification completed.
- `POST /api/sessions/bulk-delete` reports per-session outcome rather than
  failing wholesale, so one refused or missing session does not strand the rest.
- The listing cache is dropped inside `deleteLocalSession`, so a removed row
  disappears on the next fetch instead of lingering for its 60 s TTL.
