# ENG-017 Fix: PID-lock false "another instance running" on PID reuse

- **status**: completed
- **priority**: P1
- **owner**: roy
- **createdAt**: 2026-05-22

## Symptom

After the API process dies (e.g. killed without clean release), a restart can
fail with `pid_lock_failed_another_instance_running` / `exitDuplicateInstance`
even though no BKD instance is running. The frontend then serves `/api/*` as an
SPA fallback (HTTP 200 HTML), so the API appears "down".

## Root cause (`apps/api/src/pid-lock.ts`)

The lock holder is identified too loosely, so a **reused PID** (the dead
instance's PID recycled by an unrelated process) is mistaken for a live BKD
instance:

1. `isBkdByProcfs()` returns `true` when `/proc/<pid>/cmdline` merely contains
   `bun` (or `bkd`). On a host running many `bun` processes (sibling projects,
   tooling), any reused PID that happens to be a bun process matches.
2. `isBkdProcessAlive()` returns `true` in inconclusive cases:
   - `procResult === false && httpResult === undefined → true`
   - both inconclusive → `true`
   So a reused PID + an API not yet listening is treated as a duplicate.

The check never ties the locked PID to *the specific process that wrote the
lock*; `kill(pid,0)` + a substring/heuristic cannot detect PID reuse.

## Fix

Make the lock identity PID-reuse-safe via the process **start time**:

- Lock file content becomes `"<pid>:<starttime>"` where `starttime` is field 22
  of `/proc/<pid>/stat` (clock ticks since boot) captured at acquire time.
- `isLockHolderAlive(content)`:
  - dead PID → not held;
  - PID alive but recorded start time != current start time → **reused PID →
    stale** (take over);
  - start times match → genuinely the same process → held (exit as duplicate);
  - legacy lock without start time, or `/proc` unavailable → fall back to the
    HTTP identity probe (`/api` name === `bkd-api`), which only confirms a real
    BKD on the port (no more `bun` substring guessing).
- Remove `isBkdByProcfs` (the over-broad matcher); keep `isBkdByHttpProbe` for
  the non-Linux / legacy fallback. `releasePidLock` already extracts the PID via
  `parseInt`, so the new format is compatible.

## Scope

- `apps/api/src/pid-lock.ts` only.
- test: a lock holding a live non-matching start time (or a dead PID) is treated
  as stale; a matching one is held.

## Verification

- `bun run test`, `bun run lint`, tsc clean.
- Manual: stale `bkd.pid` (dead/reused PID) no longer blocks startup.

## Result (verified)

- `pid-lock.ts`: lock content is now `"<pid>:<starttime>"`;

  locks / non-Linux. Removed the over-broad `isBkdByProcfs` (`bun` substring).
  `getProcessStartTime` + `isLockHolderAlive` exported for testing.
- New `test/pid-lock.test.ts`: same pid+starttime held; reused pid (mismatch)
  stale; dead pid stale; garbage stale.
