# ENG-026 Show live context-window usage for claude-code issues

- **status**: completed
- **priority**: P2
- **owner**: claude
- **createdAt**: 2026-08-02

## Description

Surface a claude-code-only context meter (current context tokens vs model
context window, like the TUI `/context` at water-level granularity — the
full system-prompt/tools/messages breakdown is not available over headless
stream-json).

## Scope

- Claude executor: add `--include-partial-messages` so `message_delta`
  carries usage and the existing `parseMessageDelta` emits token-usage
  entries (input + cache_read + cache_creation ≈ current context).
- Schema: `issues.context_tokens` / `issues.context_window` columns
  (drizzle-kit generated migration).
- New pipeline stage (order 16): for claude-code executions only
  (`ctx.pm.get(executionId).meta.engineType`), update `contextTokens`
  from token-usage entries; update `contextWindow` from result
  `modelUsage[*].contextWindow`; emit new `context-usage` app event.
- SSE: forward `context-usage` on `/api/events`; frontend EventBus
  listener + subscription API.
- API: `serializeIssue` + OpenAPI + shared `Issue` type.
- Frontend: `ContextUsageMeter` badge in the issue metadata bar, shown
  only for `engineType === 'claude-code'` (covers virtual engines);
  live via EventBus, initial value from the issue row; >80% amber,
  >90% red; tooltip with exact numbers. i18n en/zh.

## Out of scope

- Codex context display (explicitly excluded by request).
- Full `/context` segment breakdown (not exposed by headless CLI).
