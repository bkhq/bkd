# REL-003 Replace the self-upgrade subsystem with the lode SDK

- **status**: completed
- **priority**: P1
- **owner**: roy
- **createdAt**: 2026-08-24 00:00

## Description

Delete BKD's own download/verify/apply/restart machinery and the launcher, and drive
updates through lode via its TypeScript SDK. Package mode becomes the only packaged mode.

Acceptance criteria:

- `scripts/launcher.ts`, `scripts/compile.ts`, `apps/api/src/embedded-static.ts`,
  `apps/api/src/static-assets.ts` and the `upgrade/` download/verify/apply files are gone,
  along with the `compile` / `compile:launcher` package scripts.
- `apps/api/src/upgrade/` exposes only version info, lode state, and
  update/rollback/restart requests through the vendored SDK.
- The server reports readiness to lode (`markReady()`) after `Bun.serve()` is listening
  and keeps its existing SIGTERM graceful shutdown.
- `ROOT_DIR` resolves `ROOT_DIR` env > `LODE_DIR` > dev fallback so `data/` stays put.
- Settings UI renders lode state (current/available/status/last error) with update,
  rollback and restart actions; the auto-check toggle, progress bar, checksum badge and
  downloaded-file list are removed.
- `bun run test:api`, `bun run test:frontend` and `bun run lint` pass.

Completed 2026-08-24.

- Deleted `scripts/launcher.ts`, `scripts/compile.ts`, `embedded-static.ts`,
  `static-assets.ts`, and `upgrade/{apply,checker,checksum,constants,download,files,
  github,types,utils}.ts` plus their tests; dropped the `compile`/`compile:launcher`
  scripts and the now-unused `cleye` dependency.
- `upgrade/lode-sdk.ts` vendored verbatim from dotns/lode `sdks/lode.ts` (no npm package
  exists) and eslint-ignored so updates stay a plain file copy.
- `upgrade/service.ts` is now a façade over lode's `state.json`; routes became
  `GET /version`, `GET /status`, `POST /update|rollback|restart`.
- `server-main.ts` reports readiness after `Bun.serve()` and no longer registers an
  upgrade shutdown hook (lode restarts via SIGTERM, already handled). `root.ts` resolves
  `ROOT_DIR` env > `LODE_DIR` > dev fallback.
- Removed the settings "old versions" cleanup category: it scanned `data/updates` and
  `data/app`, which no longer exist, and deleting lode's `versions/` would break rollback.
- Shared `UpgradeStatus`/`VersionInfo`/`LodeStatus` types added to `@bkd/shared`.
- About tab now shows a `lode` badge from `supervised` (the hand-written client type still
  declared the removed `isCompiled`/`isPackageMode` fields).
- Verified end-to-end against lode v0.1.0: packaged 0.0.7, seeded it, booted under lode
  (ready token written, version committed as last_good, serving in ~2s), then drove
  `POST /api/settings/upgrade/restart` — restart_nonce bumped, lode relaunched the child,
  service back within 2s.
- `bun run lint`, `bun run test:api` (604 pass), `bun run test:frontend` (57 pass) green.
