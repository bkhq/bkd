# ENG-037 Show Codex subscription usage in the settings usage panel

- **status**: completed
- **priority**: P2
- **owner**: roy
- **createdAt**: 2026-09-10

## Description

The settings usage panel (ENG-020, ENG-021) only reports Claude subscription
utilization. Users running Codex have no way to see how much of their ChatGPT
plan is left without dropping to the Codex TUI.

Codex exposes the same data the TUI renders through the app-server JSON-RPC
method `account/rateLimits/read`, which returns a `RateLimitSnapshot`:

```jsonc
{
  "rateLimits": {
    "limitId": "codex",
    "primary":   { "usedPercent": 48, "windowDurationMins": 10080, "resetsAt": 1789218429 },
    "secondary": null,
    "planType": "pro"
  }
}
```

`resetsAt` is a unix timestamp in seconds. A snapshot of the same shape is
persisted by the CLI in its session rollouts (snake_case there:
`used_percent` / `window_minutes` / `resets_at`), so parsing accepts both
spellings.

The alternative — reading `~/.codex/auth.json` and calling
`https://chatgpt.com/backend-api/codex/usage` the way the Claude panel calls
Anthropic — was rejected: the endpoint is undocumented, answered 403 on probe,
and would make BKD responsible for refreshing the OAuth token. Going through
the CLI keeps token handling inside Codex.

Acceptance criteria:

- `GET /api/engines/codex/usage` returns primary/secondary windows plus the
  plan type, or an unavailable envelope (`not_installed`, `unauthenticated`,
  `unsupported`, `upstream_error`).
- The RPC runs on demand only (panel open / refresh button), never on a timer.
- The settings usage panel renders a Claude block and a Codex block; one
  refresh reloads both.
- Parsing is defensive over camelCase and snake_case and never throws.

## Notes

Completed 2026-09-10. Reuses the short-lived app-server pattern already used by
`queryCodexModels()` and `verifyAuth()` in the Codex executor; `JsonRpcSession`,
`JSONRPC_TIMEOUT` and `resolveBinaryOnly()` are now exported from
`executors/codex/executor.ts` for `executors/codex/usage.ts`.

Verified against a live Codex CLI (`/root/.local/bin/codex`) through the Hono
app: `GET /api/engines/codex/usage` returned
`{"available":true,"primary":{"usedPercentage":46,"windowMinutes":10080,"resetsAt":"2026-09-16T12:14:50.000Z"},"secondary":null,"planType":"pro"}`.
Only `parseRateLimits` is covered by a unit test — a route test would spawn the
CLI on every run.

Out of scope: credits balance / spend controls, the `rateLimitsByLimitId`
multi-bucket view, usage history, and an offline fallback that reads the last
snapshot out of `~/.codex/sessions`.
