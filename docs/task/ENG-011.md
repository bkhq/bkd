# ENG-011 Generic schema safety-net (snapshot-driven self-heal)

- **status**: completed
- **priority**: P1
- **owner**: claude
- **createdAt**: 2026-05-16

## Goal

A general fallback so any DB — regardless of how inconsistent
`__drizzle_migrations` is, how old the origin version, or what future
journal/hash drift occurs — converges to the latest schema. Not a
per-migration patch.

## Design

`ensureSchema(sqlite, migrationsDir)` in a new
`apps/api/src/db/ensure-schema.ts` (bun:sqlite + fs only, no drizzle-orm,
consistent with `repair.ts`):

- Source of truth = highest-numbered `meta/NNNN_snapshot.json` (verified
  available in dev, package, and compiled-binary modes). No snapshot →
  no-op.
- Diff snapshot vs live DB, apply only **additive, idempotent** repairs:
  - missing table → `CREATE TABLE` (columns, single/composite PK, notNull,
    default, autoincrement; FK/CHECK best-effort omitted)
  - missing column → `ALTER TABLE ADD COLUMN` (NOT NULL without default →
    added nullable, SQLite restriction)
  - missing index → `CREATE [UNIQUE] INDEX` (incl. partial `where`)
- Destructive divergence (extra/renamed/retyped/dropped) → **reported
  only**, never auto-changed.
- Returns `{ tablesCreated, columnsAdded, indexesCreated, divergent }`.

Integration (full scope, both points — the real safety net):

1. `repair.ts` (fix-db): after prefix reconcile + tail apply, run
   `ensureSchema`; expose as `RepairResult.schema`.
2. `db/index.ts` `verifySchema()`: on missing schema, run `ensureSchema`
   once, recompute; only `process.exit(1)` if still missing. Strictly
   better than today's unconditional exit; additive-only; fully logged.

## Decisions

- D2: snapshot as source (no drizzle-orm dep; all modes). Chosen.
- D3: NOT NULL w/o default added nullable. Accepted.
- D1: full scope (both integration points) per the "must self-heal"
  requirement.

## Scope

- `apps/api/src/db/ensure-schema.ts` (new)
- `apps/api/src/db/repair.ts` (call + result field)
- `apps/api/src/db/index.ts` (`verifySchema` self-heal)
- Tests: `ensure-schema.test.ts` (new); update `db-repair.test.ts`
  assertions for the new result field.
- No API route / DB schema / migration changes.
