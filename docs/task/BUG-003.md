# BUG-003 — Fix create issue and process manager access in cockpit (ReviewPage)

## Problem

Two related UX regressions in the cockpit (`/review`) view:

1. **Create issue goes to wrong project**: When clicking the "+ New" button in CockpitTopBar, the issue is created in the "default" project instead of the currently viewed project.
2. **No process manager access**: There is no UI entry point to open the process manager drawer from the cockpit view.

## Root Cause

### Bug 1: Wrong project on create

- `CreateIssueDialog` reads `projectId` from `useParams()`: `const { projectId = 'default' } = useParams<{ projectId: string }>()`
- ReviewPage routes (`/review`, `/review/:projectAlias/:issueId`) do **not** have a `projectId` URL parameter
- `CockpitTopBar` resolves the correct `projectId` from `projectAlias` but does **not** pass it when calling `openCreateDialog()`
- Result: `CreateIssueDialog` always falls back to `'default'`

### Bug 2: Missing process manager entry

- `IssueListPanel` (used by IssueDetailPage) has an `Activity` icon button that calls `toggleProcessManager()`
- `ReviewListPanel` (used by ReviewPage) does **not** have this button
- `CockpitTopBar` also lacks a process manager button in its action cluster
- Result: no way to open `ProcessManagerDrawer` from the cockpit

## Proposal

### Bug 1 — Create issue with project selection support

**Core fix:** Thread `projectId` through panel-store so cockpit knows which project to create into.

1. Add `createDialogProjectId: string | undefined` to `PanelStore`
2. Change `openCreateDialog(statusId?: string)` → `openCreateDialog(statusId?: string, projectId?: string)`
3. In `CreateIssueDialog`, resolve effective projectId:
   - Priority: `createDialogProjectId` from store → `useParams().projectId` → undefined
   - When **no projectId is resolved** (e.g. empty `/review` dashboard), show a **project selector** at the top of the form
   - When **projectId is resolved** (from store or URL), use it directly (no selector shown)
4. In `CockpitTopBar`, pass `projectId` when calling `openCreateDialog()`
5. In `ReviewListPanel`, pass active issue's `projectId` when calling `openCreateDialog()`

### Bug 2 — Add process manager buttons

1. Add `Activity` icon button to `CockpitTopBar` action cluster (`toggleProcessManager()`)
2. Add `Activity` icon button to `ReviewListPanel` header (`toggleProcessManager()`)

## Files Involved

1. `apps/frontend/src/stores/panel-store.ts` — add `createDialogProjectId` state
2. `apps/frontend/src/components/kanban/CreateIssueDialog.tsx` — add project selector + resolve logic
3. `apps/frontend/src/components/cockpit/CockpitTopBar.tsx` — pass projectId + add Activity button
4. `apps/frontend/src/components/issue-detail/ReviewListPanel.tsx` — add Activity button
5. `apps/frontend/src/components/issue-detail/IssueListPanel.tsx` — pass projectId to openCreateDialog (consistency)
