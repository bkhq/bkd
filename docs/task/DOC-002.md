# DOC-002 Serve lode.toml from the repository instead of every release

- **status**: completed
- **priority**: P3
- **owner**: roy
- **createdAt**: 2026-08-26 10:30

## Description

`docs/bkd.lode.toml` is copied into every release as `bkd.lode.toml`, and the
install instructions fetch it from `releases/latest/download/`. The file is
operator-owned configuration that carries no version information — the update
asset name is deliberately fixed — so re-publishing it per release buys nothing
and means a config correction only reaches operators at the next release.

Acceptance criteria:

- The install instructions fetch the config from the repository.
- The release stops carrying it as an asset.
- Every place that documents the config points at the same URL.

## ActiveForm

Serving the lode config from the repository.

- **blocked by**: (none)
- **blocks**: (none)

## Notes

- The repository is public and the raw URL answers 200 unauthenticated, so no
  credentials are involved.
- Trade-off accepted: the raw URL always serves the tip of `main`, which can be
  ahead of the release an operator is installing. That is harmless while the
  config stays version-independent, and it is what makes a fix land immediately.
- `DEPLOYMENT.md` and `migrate-to-lode.ts` still ship as assets. The same
  argument applies to them, but the user asked only about the config.
- 2026-08-26 10:30 — Requested directly by the user; implementation started.
- 2026-08-26 10:45 — Implementation and verification completed.
- The file stays at `docs/bkd.lode.toml`; only how it is served changed. Its own
  header said "Published with every release", which is now false, so that was
  corrected too.

## Verification

- `https://raw.githubusercontent.com/bkhq/bkd/main/docs/bkd.lode.toml` answers
  200 without credentials; the repository is public.
- No reference to `releases/latest/download/bkd.lode.toml` survives anywhere in
  the repository.
- The workflow no longer copies, uploads or advertises the config: the
  `Collect operator files` step, the artifact list, the `Prepare assets` copy,
  the `gh release upload` list and the release-notes asset table all dropped it.
- `release.yml` still parses as YAML, and every relative link in the two READMEs
  and the deployment guide resolves.
- The next release is the real check — the asset list should show four entries
  rather than five.
