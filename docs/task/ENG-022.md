# ENG-022 Fix per-issue token/cost totals parsing (Claude + Codex)

- **status**: completed
- **priority**: P1
- **owner**: claude
- **createdAt**: 2026-08-02

## Description

`issues.totalInputTokens/totalOutputTokens/totalCostUsd` accumulate via the
order-15 pipeline stage on `turnCompleted` entries, but both normalizers read
fields that do not exist on the wire, so totals stay 0 (verified against the
local DB: all claude-code issues have 0 totals and result metadata carries no
token fields).

Root causes (verified against Claude Code 2.1.220 docs and the codex 0.144.3
`app-server generate-json-schema` bundle):

- Claude `parseResult` reads top-level `input_tokens` / `output_tokens` /
  `cost_usd`; the real result message carries `total_cost_usd` + nested
  `usage.{input_tokens, cache_creation_input_tokens, cache_read_input_tokens,
  output_tokens}` + per-model `modelUsage`.
- Codex `handleTurnCompleted` reads `turn.usage`; the `Turn` schema has no
  `usage` field. Token data arrives via `thread/tokenUsage/updated`
  (`params.tokenUsage.{last,total}` breakdowns + `modelContextWindow`), which
  the normalizer also misreads (`params.usage.*`).

## Scope

- `executors/claude/normalizer.ts` — `parseResult`: cost from
  `total_cost_usd ?? cost_usd`; tokens fallback chain top-level → `usage`
  (input = input + cache_creation + cache_read, same convention as
  `parseMessageDelta`); keep cache breakdown + `modelUsage` in metadata.
- `executors/claude/normalizer-types.ts` — add `total_cost_usd` to
  `ClaudeResult`.
- `executors/codex/normalizer.ts` — fix `thread/tokenUsage/updated` field
  paths; track per-turn token deltas from the `total` breakdown (baseline
  initialized to `total - last` on first sight); merge accumulated turn
  tokens (incl. `cachedInputTokens`, `reasoningOutputTokens`) into the
  `turn/completed` entry metadata; keep legacy `turn.usage` read as fallback.
- Tests first (RED → GREEN): real wire-format fixtures in
  `claude-normalizer.test.ts` and `codex-normalize-log.test.ts`.

## Out of scope

- DB schema changes (existing columns suffice; breakdown lives in metadata).
- Backfill of historical issues (source data was never persisted).
- Frontend display of totals (separate task if requested).

## Notes

- Claude convention: `usage.input_tokens` excludes cache tokens
  (Anthropic semantics); totals use input + cache_creation + cache_read.
- Codex `outputTokens` includes `reasoningOutputTokens` (subset detail);
  `inputTokens` includes `cachedInputTokens`.
- Old issues keep 0 totals — accepted.
