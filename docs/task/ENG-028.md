# ENG-028 Codex protocol conformance gaps (0.144.x)

- **status**: completed
- **priority**: P1
- **owner**: claude
- **createdAt**: 2026-08-13

## Description

Gaps found by diffing our implementation against the generated schema of
codex-cli 0.144.3 (`codex app-server generate-json-schema`):

1. `initialize` sends `capabilities: { experimental_api: true }`. The schema
   field is `experimentalApi` (camelCase), so the flag is silently dropped
   and the experimental API is never enabled. Three call sites:
   `protocol.ts` (execution), `executor.ts` (`queryCodexModels`, `verifyAuth`).
2. Two server requests are answered with `-32601`:
   - `item/permissions/requestApproval` (new): the agent's escalation request
     for network / extra filesystem access. Per codex
     `bespoke_event_handling.rs`, a client error reply is treated as
     "granted empty permissions" — i.e. a silent denial.
   - `mcpServer/elicitation/request`: already observed 3× in production logs
     (`codex_protocol_unknown_server_request`).
3. `thread/status/changed` is parsed as if `params.status` were a string, but
   the wire value is an object (`{"type":"active","activeFlags":[...]}` /
   `{"type":"systemError"}`). Thread-level system errors are never surfaced.
4. Thread item types `subAgentActivity`, `hookPrompt` and `sleep` are not
   normalized, so they are invisible in the UI (relevant with
   `features.multi_agent = true`).
5. The shared stderr drain logs Codex output under the `claude_protocol_io`
   message name.

## Scope

- `executors/codex/protocol.ts` — `experimentalApi`; server-request response
  map takes the request params; grant `item/permissions/requestApproval` by
  echoing the requested profile (`scope: 'session'`); decline
  `mcpServer/elicitation/request`.
- `executors/codex/executor.ts` — `experimentalApi` in both short-lived
  sessions.
- `executors/codex/normalizer.ts` — object-shaped `thread/status/changed`;
  `subAgentActivity` / `hookPrompt` / `sleep` items.
- `engines/issue/streams/consumer.ts` — engine-neutral stderr log name.
- `test/codex-protocol.test.ts`, `test/codex-normalize-log.test.ts`.

## Out of scope

- `item/tool/call` (client-side dynamic tools) and `attestation/generate`
  (opt-in via `requestAttestation`) — not reachable with our capabilities.
- `turn/steer` adoption.
