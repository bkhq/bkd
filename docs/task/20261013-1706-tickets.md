## Description

Implement the decision-event contract from the `bkd` skill
(`skills/bkd/references/decision-events.md` in `zzci/skills`) inside BKD, so a
coordinating agent can raise one event per question that needs the user, the
user decides in a global inbox, and BKD wakes the coordinator with a follow-up.

Acceptance criteria:

- The contract routes are served under `/api/decisions/events` (create, get,
  list, patch, decision, ack, withdraw) with the state machine
  `open -> decided -> applied` and `open -> withdrawn`; wrong-state
  transitions return 409.
- The user can also close an event (from `open` or `decided`); `closed` is
  terminal and sends no follow-up.
- Deciding sends `[event-decision eventId=… campaignId=…]` to the notify issue
  as a follow-up; a failed notification leaves the event `decided`.
- A global `/decisions` page shows waiting, decided and historical events and
  lets the user decide by option and/or instruction, or close; the sidebar shows the
  open count; agent-side changes appear without a reload.
- Shared Zod schemas and OpenAPI metadata; i18n keys in `en.json` and
  `zh.json`.
