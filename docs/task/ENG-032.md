# ENG-032 Fix subagent activity never reaching the chat

- **status**: completed
- **priority**: P0
- **owner**: roy
- **createdAt**: 2026-08-25 14:45

## Description

Subagent activity added in [ENG-031](ENG-031.md) does not appear in the issue
chat. Reproducing the CLI call with BKD's exact flags confirmed the engine side
is fine — 5 subagent-tagged entries and 3 lifecycle events per dispatch, which
the normalizer and the chat rebuilder both handle correctly. Two defects in
BKD's own code prevent that data from reaching the screen.

**1. The capability probe never succeeds on an npx install.**
`supportsSubagentForwarding()` passed `resolveBaseCmd()` straight to
`runCommand` as `argv[0]`. When no `claude` binary is found that value is the
whole string `npx -y @anthropic-ai/claude-code`, which `nodeSpawn` rejects:

```
SPAWN ERROR: ENOENT - no such file or directory, posix_spawn 'npx -y @anth…'
```

The probe caught the error, returned false, and `--forward-subagent-text` was
never passed, so no subagent data was produced at all. `CommandBuilder.build()`
tokenizes the same value correctly, which is why spawning the engine still
worked.

**2. Only `AgentToolItem` renders the nested thread.**
`ToolItemRenderer` routes to it on `toolName === 'Agent' || kind === 'agent'`.
CLI versions that name the tool `Task` fall through `classifyToolAction`'s
default to `kind: 'tool'` and land on `ToolWithArgsItem` or `GenericToolItem`,
neither of which reads `item.subagent` — the thread is dropped silently.

A third, cosmetic issue compounds both: the thread sits inside a collapsed
`<details>` with no indication that it holds anything.

Acceptance criteria:

- `--forward-subagent-text` is passed unconditionally; the probe is gone and the
  minimum CLI version is documented.
- A tool call that carries a subagent thread renders it regardless of the tool's
  name.
- The collapsed row shows that a subagent thread is present and its status.
- Focused frontend and API tests pass, followed by repository lint, typecheck
  and build verification.

## Notes

- The probe is removed rather than repaired: per the user, requiring a current
  Claude Code CLI is the supported answer.
- `--forward-subagent-text` is verified present in CLI 2.1.231. An older CLI now
  fails to start rather than silently degrading, which is the intended trade.
- 2026-08-25 14:45 — Reported by the user; implementation started.
- 2026-08-25 15:05 — Implementation and verification completed.
- The minimum CLI requirement is recorded in `CLAUDE.md` next to the engine's
  protocol description.
- `AgentToolItem` reads `metadata.input.{description,prompt,subagent_type}`,
  which the `Task` tool populates identically, so routing `Task` there needed no
  further change.
