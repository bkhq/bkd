# ENG-012 Create dialog ignores project-level default engine

- **status**: completed
- **priority**: P1
- **owner**: claude
- **createdAt**: 2026-05-16

## Symptom

User sets a project's default engine to `codex` (model `gpt-5.5`). New
issues still start with the **global** default engine (`claude-code`); the
model appears to take effect but the engine does not.

## Root cause

`apps/frontend/src/components/kanban/CreateIssueDialog.tsx`:

- `resolvedEngineType` (≈ L86–91) derives the default engine **only** from
  `engineSettings?.defaultEngine` (global) then `installedEngines[0]` — it
  never consults `project.defaultEngine`, although `project` is already
  available via `useProject(projectId)` (L55).
- `handleSubmit` (≈ L136) sends `engineType: resolvedEngineType || undefined`,
  so even when the user makes no explicit choice it sends the **global**
  engine. The server (`routes/issues/create.ts:33`,
  `body.engineType ?? null`) then treats it as an explicit override and
  **bypasses its own correct precedence** (explicit → project → global →
  fallback).
- `model` is sent as `modelId || undefined` (`''` when untouched →
  `undefined`), so the server precedence still runs for the model — which is
  why model/engine behave asymmetrically.

Only `CreateIssueDialog` has this defect; other matches are settings
dialogs, not issue-creation paths. The server resolver is already correct.

## Fix (unified resolution authority)

Principle: the **server** is the single authority for default resolution;
the frontend sends engine/model only when the user explicitly overrides.

1. `handleSubmit`: send `engineType: engineType || undefined` (raw user
   selection; empty → let the server decide). `model` already follows this.
   → server precedence makes the project default engine win; no server or DB
   change.
2. Add a small shared resolver
   `apps/frontend/src/lib/engine-defaults.ts` mirroring the server precedence
   (user → `project.defaultEngine` → global → first installed). Use it for
   the dialog's **display** (engine selector value + model list), so the UI
   shows the effective default without forcing it into the request.
