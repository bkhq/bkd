# ENG-015 Virtual engines: accept virtual ids in engine settings routes

- **status**: completed
- **priority**: P2
- **owner**: roy
- **createdAt**: 2026-05-22
- **extends**: ENG-013, ENG-014

## Problem (from testing)

Reported: a virtual engine "cannot be deleted / cannot edit URL+key / cannot
be set as default engine".

Reproduced in-browser on current code:
- Delete and edit URL/Token in the Virtual Engines editor **work** (verified —
  the earlier confusion was an env-stored config showing empty Base URL/Token
  fields).
- **Set-as-default genuinely fails**: `PATCH /api/engines/default-engine`
  validates `z.enum(['claude-code','codex'])` and rejects a virtual id (400).

The same closed-enum check also blocks the per-engine settings routes that the
virtual engine's EngineCard uses (`PATCH /:engineType/settings`,
`/:engineType/hidden-models`, `GET /:engineType/models`).

## Fix

In `routes/engines.ts`, accept a virtual engine id wherever a real engine type
is currently required:
- `setDefaultEngine`: valid if real engine OR configured virtual id.
- `setEngineModel` / `setHiddenModels`: same.
- `getEngineModels`: for a virtual id, return its discovered models
  (`fetchVirtualEngineModels`) instead of 404.

Helper `isKnownEngineId(id)` = `engineRegistry.get(id) || getVirtualEngine(id)`.
create.ts already resolves a virtual id from the global/project default, so a
virtual default engine works end-to-end once the PATCH accepts it.

## Scope

- `apps/api/src/routes/engines.ts` only.
- tests: default-engine + per-engine settings accept a virtual id.

## Verification

- `bun run test`, `bun run lint`, tsc clean.
- Manual: set the virtual engine as default in settings → persists; new issue
  with no explicit engine resolves to it.

## Result (verified)

- `routes/engines.ts`: added `isKnownEngineId(id)` (real engine OR virtual);
  `setDefaultEngine`, `setEngineModel`, `setHiddenModels` now accept a virtual
  id; `getEngineModels` returns a virtual engine's discovered models
  (`fetchVirtualEngineModels`), unknown id still → 400 (preserves contract).
  Removed the now-unused `engineTypeEnum`.
- Browser repro confirmed delete + edit-URL/Token already work; only
  set-as-default was broken — now fixed.
- tests: `api-virtual-engines.test.ts` — default-engine + per-engine model +
  hidden-models accept a virtual id; unknown id rejected.

Verification:
- `bun run test:api` 521 pass / 0 fail; `bun run lint` 0 errors; tsc clean.
- Live (`bkd.localhost`): `PATCH /api/engines/default-engine` with the virtual
  id → 200 (was 400).
