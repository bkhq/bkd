# ENG-016 Fix: startup schema self-heal never fires (computeMissing detects 0 tables)

- **status**: completed
- **priority**: P1
- **owner**: roy
- **createdAt**: 2026-05-22

## Symptom

Creating an issue with a virtual engine failed: `table issues has no column
named engine_profile_id`. The dev DB never got migration 0021 applied, and the
snapshot-driven safety net (ENG-011) did not repair it on startup.

## Root cause

`apps/api/src/db/index.ts` `computeMissing()` introspects the Drizzle schema via
`(value as any)?._` to read `meta.name` / `meta.columns`. In drizzle-orm 0.45.2
that accessor is `undefined`, so the loop `continue`s for **every** export →
`expectedTables` is empty → `computeMissing()` always returns `[]` →
`verifySchema()` always logs `schema_verification_passed` and **never calls
`ensureSchema()`**. The self-heal is dead code at startup.

Separately, `migrate()` aborts early on this dev DB (re-applies an already-present
column from an inconsistent `__drizzle_migrations` history — ENG-009/010 legacy),
so 0021 is skipped; with the safety net dead, the missing column surfaced only at
query time.

Verified: `is(value, SQLiteTable)` + `getTableConfig(value)` correctly detects
all 11 tables and `issues.engine_profile_id`; the old accessor detects 0.

## Fix

- `db/index.ts`: detect tables with `is(value, SQLiteTable)` and read columns via
  `getTableConfig(value).columns` (proper drizzle API) instead of `._`.
- Extract the schema→`[table, cols][]` mapping into a side-effect-free, exported
  helper so it is unit-testable without triggering startup migrate/verify.

## Scope

- `apps/api/src/db/index.ts`, small helper (in `ensure-schema.ts` or new file).
- test: helper detects tables incl. `issues.engine_profile_id`.

## Verification

- `bun run test`, `bun run lint`, tsc clean.
- The dev DB was unblocked immediately via `bun src/index.ts fix-db`
  (`repairDatabase` runs `ensureSchema` unconditionally) — issue create now 201.
- After the fix, a startup against a DB missing a column self-heals.

## Result (verified)

- `apps/api/src/db/schema-introspect.ts` (new, side-effect-free):
  `expectedSchemaTables()` using `is(value, SQLiteTable)` + `getTableConfig`.
- `db/index.ts`: `computeMissing()` now uses `expectedSchemaTables()` (was the
  broken `._` accessor that detected 0 tables).
- dev DB unblocked immediately via `bun src/index.ts fix-db`.

Verification:

  (`columnsAdded: ["issues.engine_profile_id"]`) → `schema_verification_passed`
  → column restored.
- `bun run test:api` 523 pass / 0 fail (incl. new `schema-introspect.test.ts`);
  `bun run lint` 0 errors; tsc clean.
- Live: issue create with the virtual engine → 201 (was 400 "no column
