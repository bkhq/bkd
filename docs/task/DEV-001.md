# DEV-001 Consolidate dev env onto a single root .env (nsl dev)

- **status**: completed
- **priority**: P2
- **owner**: roy
- **createdAt**: 2026-05-22

## Goal

Mirror the `/app/bithk` dev pattern for env: both dev servers (api + Vite)
read one shared **root `.env`** via `--env-file`, instead of separate
per-workspace dev `.env` files. nsl names stay hardcoded (`bkd`, `bkd:/api`) —
no `APP_NAME` / `BASE_PATH` parameterization.

## Approach (non-destructive)

1. root `package.json` `dev`: `bun --env-file=.env run --filter @bkd/api
   --filter @bkd/frontend dev` (root `.env` injected into both children).
2. `apps/api` `dev`: add `bun --env-file=../../.env` so `dev:api` standalone
   also reads the root `.env`.
3. `apps/frontend/vite.config.ts`: point `loadEnv` at the monorepo root so the
   Vite dev server reads the root `.env` whether launched via the root `dev`
   or `dev:frontend` standalone.
4. root `.env.example`: add a Vite Dev section (`VITE_DEV_PORT`,
   `VITE_DEV_HOST`) so one template covers both.
5. create a root `.env` (gitignored, additive) consolidating current local
   values (`PORT=3010`, `VITE_DEV_PORT=3000`).
6. `CLAUDE.md`: update the env convention note.

`bun --env-file=<missing>` is a no-op (verified), so the scripts are safe even
without a root `.env`. Existing local `apps/*/.env` files are left untouched
(`apps/api/.env` still serves production `start` + drizzle); `apps/frontend/.env`
is superseded for dev.

## Scope

- `package.json`, `apps/api/package.json`, `apps/frontend/vite.config.ts`,
  `.env.example`, `.env` (new, gitignored), `CLAUDE.md`.
- No app/runtime code, no schema.

## Verification

- `bun run dev` brings up both via nsl; `http://bkd.localhost` serves the app
  and `/api/*` reaches the API.
- `bun run dev:api` and `bun run dev:frontend` work standalone.
- `bun run lint` green.

## Result (verified)

- root `package.json` `dev`: `bun --env-file=.env run --filter @bkd/api
  --filter @bkd/frontend dev`.
- `apps/api` `dev`: `nsl run --name bkd:/api bun --env-file=../../.env --hot
  src/index.ts`.
- `apps/frontend/vite.config.ts`: `loadEnv(mode, path.resolve(import.meta.dirname,
  '../..'))` — reads the root `.env`.
- root `.env.example`: new "Dev (root .env …)" section (`PORT`,
  `VITE_DEV_PORT`, `VITE_DEV_HOST`). `apps/frontend/.env.example` now points to
  the root file.
- created root `.env` (gitignored) with `PORT=3010`, `VITE_DEV_PORT=3000`,
  `VITE_DEV_HOST=0.0.0.0`.
- `CLAUDE.md` env-convention bullet updated.

Verification:
- `bun run lint`: 0 errors (5 pre-existing warnings).
- `bun run dev` in tmux: both servers launch via nsl with the new
  `--env-file=../../.env` (API) and root-.env-aware Vite; both report Running,
  no errors. `bun --env-file=<missing>` confirmed a safe no-op.

## Notes

- nsl name stays hardcoded `bkd` (per request — no APP_NAME/BASE_PATH
  parameterization).
- The host already has another `bkd`-named nsl instance (`/app/zzci/access`)
  holding `bkd.localhost`; that is a pre-existing environment collision
  unrelated to this change and out of scope (would only be addressed by name
  parameterization, which was explicitly declined).
- Existing local `apps/api/.env` / `apps/frontend/.env` were left untouched;
  `apps/frontend/.env` is now superseded for dev.
